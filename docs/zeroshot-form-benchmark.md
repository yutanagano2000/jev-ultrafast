# Zero-shot form benchmark

The loop drives a multi-page business application form (a real electricity
retailer portal, JSF/PrimeFaces) from one natural-language goal plus a profile
JSON. No selectors, field values, or site workflow are hardcoded — the model
chooses among observed actions only.

## What the run needs

1. **A Chromium session via browser_harness** — `ensure_daemon()` starts it.
   The tab must already sit on a page inside the authenticated flow (deep links
   into the middle of a JSF flow return the site's own error page).
2. **An authenticated site session** — log in through the site's normal UI
   first (assisted login is fine; the benchmark measures form operation, not
   SSO). If cookies expire, log in again — direct REST/session tricks are
   brittle against OpenAM-style handlers.
3. **TypeSafe + a text model** — `.env` supplies `TYPESAFE_API_KEY`,
   `TEXT_MODEL_*` (any OpenAI-compatible endpoint).
4. **Optional rescue model** — `RESCUE_MODEL_API_KEY`,
   `RESCUE_MODEL_BASE_URL`, `RESCUE_MODEL`. Fires only after five consecutive
   weak outcomes, capped at 15 calls/run with a 5-step cooldown. It chooses
   from the same filtered action space and never receives field values.
5. **A profile JSON + a goal file** — values are injected by the
   `field_source` decision, never generated by the executor.

## Run

```bash
RESCUE_MODEL_API_KEY=... \
RESCUE_MODEL_BASE_URL=http://127.0.0.1:8799/v1 \
RESCUE_MODEL=sonnet \
python -u zeroshot.py --attach <url-substring> --profile profile.json --goal-file goal.txt
```

`--attach` selects the tab by URL substring; use a page-specific fragment when
several flow tabs are open. `-u` keeps stdout unbuffered.

## Reading the log

Each action is one JSON line in the run log:

- `outcome`: `value_set`, `navigated`, `unchanged`, `same_url_changed`,
  `no_value`, `stale`, `regressed`, `dialog_opened`, `dialog_answered`
- `detail`: the alert/confirm text the action produced — the page's own
  explanation of what blocked it
- `errsig`: the error + required-empty signature the action ran under

Success = reach the confirmation page. Final submit is never pressed (the goal
says so, and the operator verifies independently — a DONE choice is not proof).

## Mechanics worth knowing

- `page.fields` — per-control table (label, required, value, locked, error,
  action ids, `next` = first unfinished required field in DOM order).
- `reveal` actions scroll a specific off-screen required field into view.
- `stale` is recorded like any outcome — an untouchable target parks itself
  instead of burning the decision budget.
- A stuck full-viewport overlay (ajax mask with no dialog) is detected as
  `overlay`; while present only `dismiss`/`wait`/`dialog` actions are legal.
- `DONE`/`BLOCKED` are not offered while a native dialog is pending or
  `required_empty` is non-empty.
- Locked (disabled + valued) controls cannot carry live errors — residual
  inline messages near them are ignored as submit residue.
